directory take 1 — aihero.dev model

Grouped by each skill's role in the process, not by your situation. Adapted from aihero.dev, which groups its 25 skills as “Getting Started / The Main Flow / Shaping / Upkeep / Productivity / Reference” — every group heading says what that group does for the flow, which holds whatever the reader's context is. Their form too: one bordered grid with hairline cells (not six cards), a numbered heading, one sentence, skills as bare command chips with no per-skill prose, and a “start with” button pinned to the bottom of every cell. Group 01 gets a real shared predicate — none of those four change your product — instead of being the leftovers.

Twenty-one skills, and where each one sits.

Every skill installs with the plugin and works today. Start anywhere. Most people start with the design loop.

We build ours. We curate the rest.

Three skills we didn't write and don't maintain, but reach for often. Install them alongside the harness — they carry no dx-harness: prefix and no catalog behind them.

  • /web-animation-designEasing, timing, and springs, argued from first principles.
  • /better-uiA second opinion on a component you've already built.
  • /make-interfaces-feel-betterThe small craft details — optical alignment, borders, hover feel.
  • What the reference buys us: dropping per-skill prose. Twenty-one one-liners is a wall of text; twenty-one chips under six honest sentences is a shape you can read in ten seconds.
  • What it costs: a chip tells you nothing. Anyone who doesn't already know what /dx-design-flow means learns nothing here, and there is no hover on touch. aihero absorbs this with a “See all 25 skills” link to a full directory page — we would need the same escape hatch, which is a second page to build.
  • The role framing survives a change of context, which is the fix for the rejected moment-of-use model: “the propose-only layer the loop routes to” is true whether or not your page exists yet.
  • Externals sit under the grid so the last thing you read is generous rather than promotional. They could also sit as a seventh cell (reads as ours — risky), in the footer (safe, easily missed), or on the /skills page once it exists.
directory take 2 — prominence, no labels

No stage names at all. Size carries the meaning. The three skills you actually type get full billing; the five passes are a quiet band, because the orchestrator routes to them and you rarely name them yourself; the engineering eight sit below as a plain list; setup, git, feedback, and the two shaping skills drop to a hairline strip. Nothing is hidden, but the page stops pretending all twenty-one deserve equal attention.

Three skills do most of the work.

There are twenty-one in the plugin. You will type three of them. The rest get routed to for you, or run once and stay out of the way.

/dx-harness:dx-design

Ask for anything

Say what you want in plain words. It works out which skill you need, answers rule questions on the spot, and hands off. Start here when you're not sure.

Routes. Never builds. /dx-harness:dx-design →
/dx-harness:dx-design-execute

Get it built

Intent, a few options, then a plan you approve before anything moves. The only skill in the plugin that changes a file in your product.

Stops for you at plan approval. /dx-harness:dx-design-execute →
/dx-harness:dx-design-critique

Find out what's wrong

Captures the page, grades it against the catalog, and hands back a numbered list with evidence. You approve by number; nothing changes until you do.

Proposes only. Changes nothing. /dx-harness:dx-design-critique →

Run once, or when you're stuck

None of these touch your product.

  • dx-design-setup — installs the per-user tools the loop relies on
  • dx-design-language — writes DESIGN.md, your project's design language
  • dx-design-research-brief — a research plan before you recruit anyone
  • dx-design-git — Gitty, git explained in plain words and done with you
  • dx-design-feedback — files an issue when the harness itself confuses you
  • Same 21 skills as take 1, re-weighted. Take 1 tells you the shape of the system; take 2 tells you what to type and lets the rest fade. Take 2 is the only one of the two that admits some skills matter more than others.
  • The residue bucket is fixed here by demoting it rather than naming it: the strip is one hairline and five rows, and its unifying line is a real property (none of these touch your product), not a stage.
  • No “start with” CTA on the strip, on purpose. A CTA is a claim that you should begin there, and you shouldn't — except for setup, which the install block at the top of the page already covers.
  • Risk: three big cells, two banded lists, and a strip is four levels of hierarchy in one section. If the section has to shrink, the strip goes first, and then those five skills appear nowhere on the homepage.
  • The curated-externals note is not repeated here. It would sit below the strip, in the same dashed frame.
