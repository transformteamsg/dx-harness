Everything on this site exists in three forms, for three readers.

**Humans read the site.** The guidance pages are written for people making judgement calls. Browse, decide, deviate with a reason.

**Humans hand skills to machines.** Skills in the [harness](/harness) are markdown instructions: human-readable guidelines packaged so an agent can execute them. You read a skill to trust it; the agent reads it to apply it. Skills don't define the bar, they carry it.

**Machines read the contract.** The catalog is the one layer precise enough to enforce automatically, so it is published twice: rendered for review at [/standards/catalog](/standards/catalog), and as data at [/standards/catalog.yaml](/standards/catalog.yaml).

Every page on this site is also available as Markdown: append `.md` to its path. So [/standards/voice-tone](/standards/voice-tone) has a clean Markdown twin at `/standards/voice-tone.md` — the page content, no site chrome. Fetch one page when you need one page.

## Wiring it into your tool

Two machine surfaces, depending on how much you need:

- [/llms.txt](/llms.txt) is the curated index — it lists every page and links each `.md` twin. Start here. Any page is also available as Markdown: append `.md` to its path (e.g. `/standards/catalog.md`).
- [/standards/catalog.yaml](/standards/catalog.yaml) is the machine source. Point your tool at it when you only need the standards.

Tiers are binding: L0 cannot be waived, L1 needs `dx-waive <ID> reason="..."` in code, L2 deviations need an inline rationale.

One thing the catalog is not: a skill. Skills apply the standard inside a session; the catalog *is* the standard. When they disagree, the catalog wins, and the skill gets fixed.

## Wire it into CI

Two layers, depending on how deep you integrate:

- **Consume the contract.** Point your tooling at
  [/standards/catalog.yaml](/standards/catalog.yaml) and grade what you build
  against each standard's `verify` and `fails_when`.
- **Run the checks.** The harness repo carries the deterministic checkers the
  catalog references (schema validation, token audit, static accessibility)
  and this site's own CI runs them on every push — install the plugin from the
  [harness](/harness) page and your repo gets the same checks
  in the design loop. Not every standard has a script; the catalog's `enforced`
  field says which are machine-checked today, and nothing unscripted is ever
  reported as "passed".
