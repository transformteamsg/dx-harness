title: Design in code
description: Make your first UI change in a real repo, from setup to a merged merge request.
---

You can make UI changes to a live product without writing code from scratch. What matters is understanding *what each step does and why*. That understanding is what keeps you safe, so this guide stays plain and explains the why as it goes.

Think of the codebase like a shared Figma file that's also live for its users. Four habits keep you safe:

- Work on your own copy, never the shared version directly.
- Start with the frontend, where you're strongest and changes are safest.
- Keep each change small, so it's easy to review and to undo.
- Let someone review it before it goes live.

One rule: don't touch the backend by accident. If a change turns out to need backend work, pause and bring in an engineer.

> **One note up front.** This guide is a designer's path, not an engineering rulebook. Teams set things up differently, so when something touches access, setup, or safety, check the specifics with your engineers.
